AI8 Native Drive — privacy notice

Reviewed against the native setup on 6 November 2026.

AI8 Native Drive is a private, single-user integration operated by BD. This notice covers the native rclone Desktop OAuth client AI8 Razer — rclone and its current AI8 Drive routines. It does not cover separate Codex or Claude connected plugins, website features, or all future AI8 capabilities.

Google authorization and information accessed

The native client requests https://www.googleapis.com/auth/drive, which allows viewing and managing all Drive files in the authorized account. The current routines use designated AI8 files and a coordination folder, but the granted permission is broader than those runtime restrictions. Google describes the scope here.

The watcher reads file identifiers, names, sizes, modification times and owner metadata. For eligible changed notices, it also reads up to the first 4,096 bytes to inspect routing information. A short notice can fit entirely within that prefix. The watcher stores metadata and derived routing hints rather than exporting the raw notice body into its queued prompt.

The heartbeat routine reads and updates an existing Drive control file. The uploaded information includes selected host, service and role delivery status, timestamps, counts and continuity references.

Purpose, storage and data flow

This information supports the owner's AI8 coordination, delivery review, status reporting and recovery continuity. Local records include cursors, file revision hashes, metadata, sender and recipient hints, delivery acknowledgments and diagnostic receipts.

Google processes the authorized API requests and stores the Drive files. Native OAuth authorization is held in the machine's rclone configuration. OAuth/client secrets, private signing keys, bus tokens, mail bodies and notice bodies are excluded from the selected local health projection.

If the owner enables the optional GitHub continuity mirror, a copy of the selected heartbeat is stored in the owner’s private GitHub repository. GitHub then processes and stores that copy under its own policies.

The native watcher can queue a fixed local status prompt to an existing CLI agent session. Remote notice text is not inserted into that prompt. During separately authorized review, the owner or a CLI assistant can retrieve document or notice content. Material supplied as assistant context may be processed by that assistant's external provider under its applicable settings and policies. This notice does not claim that all AI8 data stays on the machine.

The current native Drive polling and heartbeat routines do not themselves call models or run arenas. Research model and arena execution are outside this integration's current enabled scope.

The native integration has no advertising or analytics component. Its Google data is used for the owner's AI8 workflow. Separate Google, assistant-provider and connected-plugin services have their own data practices.

Retention and owner control

The continuity workflow preserves local cursors and receipts for review and recovery. No fixed automatic deletion period has been established; retention and cleanup are controlled by the owner.

The owner can stop the local routines and review or remove the app's Google Account access. Removing access does not itself erase existing Drive files, local records or material already provided to a separate service. Those copies require separate owner-controlled review and cleanup.

Operator and contact

The operator is BD. The operator's existing public contact is listed on MDL×DCC.org. This app has no public account registration.
