Chapter 01

Public / private documentation split

Private Rule

Do not publicly document what the Vault Host URL field is for beyond what an operator needs to use the tool. Public documentation should describe user-visible behavior, not internal routing semantics.

The public paper should explain that split-host deployment exists. It should not spell out the hidden role of the URL field, the shape of redirect wrappers, or the exact operator discipline used to keep entry pages separate from payload hosting.

Chapter 02

Vault Host URL

Internally, the Vault Host URL is the deployment root for payload pages. It serves two purposes:

  • It defines where split-host redirect pages should send users.
  • When Origin Lock is enabled, its hostname becomes the approved execution origin for the normal passphrase path.
Example:
Vault Host URL = https://example-vault.netlify.app
Payload page   = https://example-vault.netlify.app/zz.html
Chapter 03

Internal layers

Split-host air-gap

The tool can emit two host-specific output sets: payload pages for the vault host and public redirect pages for a different host. Redirect pages are themselves protected shells. After successful unlock they route to the payload host and hand off the current passphrase via hash fragment. The receiver immediately strips the hash from the address bar and auto-submits the unlock form.

Purpose

This is not invisibility in an absolute sense. It is operational separation and friction against simple repository scraping and naive rehosting.

Origin Lock + Owner Override

Origin Lock is an optional execution-context binding layer. The normal passphrase path is bound to the approved host. The Owner Override Key is a second, independent secret that remains valid anywhere.

Naming Rule

Use Origin Lock and Owner Override Key. Do not use “Trojan horse” in documentation or UI.

Managed Recovery

Managed Recovery is an optional convenience tier, not part of pure static Shield mode. The current static builder exports the recovery descriptor and embeds masked hints into the protected page. Time-limited dual-email OTP delivery is intentionally left to an external recovery gateway or service.

Important

The static builder does not send email itself. That would require secrets or a delivery backend. Keep the core product honest: the tool exports recovery metadata; the operator supplies the gateway.

When enabled, the protected page may show masked hints such as bo***@gm***.com and ax***@pr***.me. Raw addresses belong only in the private recovery descriptor.

Limits and discipline

  • Do not market Origin Lock as unbreakable DRM. It is an anti-rehost and anti-mirror layer.
  • Keep owner override long and private.
  • Keep recovery descriptors private. They are not customer deliverables.
  • Do not publish the private appendix with the public book.
  • Keep the public paper focused on outcomes and user-visible behavior.
Operator Thesis

The value is now in the combined stack: static payload protection, bundle transport, split-host routing, Origin Lock, owner override, trace, and optional managed recovery metadata. That combined architecture is where the system becomes distinctive.

This appendix is for operator use. It should travel with private deployment notes, not with the public marketing or buyer-facing package.
