📖 Help & Documentation

🎯 What Is This?

A mean-reversion paper trading simulator that connects to live crypto exchanges via WebSocket. It detects ZigZag swing patterns, enters counter-trades when price overextends, and averages down if price continues against the position. The math guarantees that every trade is closed at a profit (100% gross win rate) — price must eventually revert, and each add brings the average entry closer to current price.

Key insight: This is NOT a live trading bot. No real money is at risk. It simulates trades using real market data to test strategy configurations before going live.

🚀 Quick Start

1. Select your Symbol, Exchange, and Timeframe in the sidebar.
2. Press ▶ Start — fetches historical data, runs backtest instantly, then goes live.
3. Change any setting and press ⟳ RECALCULATE to replay the same data with new settings.
4. Use 📸 PNG for screenshots and 📋 Report to export results.

💡 Why $1 Base Makes More Than $10 Base

This confuses everyone. It's not a bug — it's the exponential sizing hitting the cap.

With Double Total sizing, position grows as 3n: $1 → $3 → $9 → $27 → $81 → $243 → $729 → $2,187 → cap. With $10 base and $5K cap, you get: $10 → $30 → $90 → $270 → $810 → $2,430 → cap. That's 8 adds vs 6 adds — the $1 base gets 2 more averaging layers before the cap bites.

More adds = tAE moves closer to price = trades close sooner = more trades in same period = more total profit. The Eff. Adds card in Row 2 shows this instantly.

Rule of thumb: Maximum profit when Eff. Adds shows the full count (e.g., 10/10). If it's red, either increase equity, increase Max Pos %, or reduce base size.

📐 Smart Leg Average (SLA)

The standard average of the last N legs can be inflated by a single monster move (e.g., a 5% flash crash in a market where normal legs are 0.5%). This inflated average causes:

• Late entries — entry threshold (0.5 × avgLeg) becomes too high
• Missed TPs — TP target (0.3 × avgLeg) becomes unreachable for normal legs

SLA caps any leg exceeding cap × median of the other legs. Default cap is 1.5×. The ✂ count shows how many legs were capped. Effect: +25 to +47 more trades per timeframe at same or better win rate.

Exception: on 30m timeframes, use cap=2.0 or higher — heavier tails mean outliers ARE the regime.

🔄 Recalculate Workflow

1. Press Start to load data and run initial backtest
2. Change any parameters in the sidebar
3. Press ⟳ RECALCULATE — replays same candles with new settings in milliseconds
4. Compare results in Row 1 — no re-fetching needed

This is how you A/B test: toggle SLA on/off, change deviation, try different sizing modes — one click each time to see the full impact over the same historical period.

🔌 Exchanges

Historical data always comes from Binance API (only exchange with browser CORS support). Live feed uses the selected exchange's WebSocket.

1s timeframe is only available on Binance (they have 1-second klines). Selecting it auto-switches exchange to Binance.

The WS keepalive pings every 20 seconds to prevent disconnections (especially on MEXC).

⚠️ Important Limitations

• No slippage simulation — entries and exits happen at exact candle close price. Real trading has slippage.

• Backtest ≠ live — historical data is clean and sequential. Live markets have gaps, latency, and order book dynamics.

• Infinite hold assumption — the strategy holds losing positions indefinitely, waiting for reversion. In live trading, extreme moves (exchange halt, black swan) can force liquidation before reversion occurs.

• The 100% WR guarantee is mathematical, not practical. It assumes: unlimited holding time, no forced liquidation, and sufficient capital for all adds. Real markets can break all three.
