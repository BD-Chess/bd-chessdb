What this page defines

AIm³ MentalArena / mRHP is an external mental/workflow layer above today’s LLMs, now represented by a local Python validation arena. It treats reasoning protocols as evolvable artifacts: roles, operators, scoring rules, output formats, memory objects, benchmark tasks, reports, and next-session seeds can be tested, mutated, scored, and improved over time.

1. Clear boundary

Yes — a new external mental layer, not model training.

AIm³ MentalArena is a new operational layer above LLMs, but it does not change the neural model. The LLM weights do not learn. The surrounding reasoning system learns: protocols, memory, scoring, tests, reports, lineage, and next-session seeds become better through explicit experiment cycles.

It is not
  • model-weight learning
  • autonomous AGI
  • proof of AI consciousness
  • wet biology
  • a random idea generator
  • a standard transformer architecture claim
It is
  • external operational learning
  • RHP improving RHP
  • protocol genes and concept capsules
  • mutation/crossover of reasoning protocols
  • benchmark tasks, scoring, lineage, reports
  • human-led multi-LLM synthesis

The core testable claim: a stable external workflow can improve the practical reasoning behavior of LLM sessions without changing the LLM itself.

3. Three names, three levels

RHP is a run. mRHP is evolution. MentalArena.py is the runtime.

RHP
One reasoning run

A structured protocol for one strong reasoning pass: roles, critique, synthesis, provenance, and next action.

seed → bridge → test → result
mRHP
Meta-RHP

RHP itself becomes the object under search. Protocol variants evolve through genes, mutation, crossover, scoring, and benchmark feedback.

RHP variants → scored lineage
MentalArena.py
External runtime

A local Python arena now exists. It tests protocol variants over time with deterministic seeds, CPU workers, checkpoint/resume, logs, leaderboards, reports, live extracts, baselines, and ablations. It does not alter LLM weights and does not self-patch while running.

runs → logs → reports → seeds
4. First challenge

Can the arena evolve a better reasoning protocol than seed RHP?

The first serious MentalArena task should not be TSP, NAS, DNA, trading, ARC, Nara, or AI8. The first task is self-referential but still empirical: can MentalArena improve the reasoning protocol that will later be used on those domains?

Why this is the right first test: before applying MentalArena to other arenas, the project must prove the spine works — protocol representation, mutation, scoring, lineage, benchmark tasks, reports, live extracts, and next-session seeds.

Too early

Domain optimization

Running MentalArena immediately on NAS, TSP, ARC, DNA, or trading would mix protocol failure with domain failure.

First target

Reasoning protocol improvement

The cleanest target is RHP itself: can we make the workflow sharper, safer, more testable, and more useful?

Later

Concept Genome Arena

Once protocol evolution works, concept capsules can become the broader search objects.

5. Protocol Genes

Small evolvable pieces of reasoning behavior.

A protocol gene is one compact unit of an mRHP variant: a role, operator, scoring rule, memory rule, report rule, safety rule, benchmark task, or live-extract behavior. The arena can mutate, combine, score, retire, or promote these genes.

mRHP_ProtocolGene - gene_id - type - title - description - role_or_operator - expected_effect - cost - risk - mutation_kind - parent_ids - status - score - notes - lineage - evidence
role_geneoperator_genescoring_geneoutput_genememory_genesafety_genebenchmark_genereport_genelive_extract_gene
Example role gene

Builder

Turns seeds into concrete artifacts, prompts, schemas, or test plans instead of staying in abstract evaluation.

Example safety gene

Abuse reviewer

Checks whether protocol optimization could become manipulation, jailbreak optimization, provenance laundering, or unsafe automation.

Example scoring gene

MentalScore

Rewards usefulness, testability, lineage, and readability while penalizing handwave, hallucination risk, verbosity, and no-next-action output.

6. Concept Capsules

Structured idea objects that survive context loss.

A concept capsule is not a random idea. It is a portable seed with mechanism, failure mode, smallest test, metrics, lineage, evidence, status, and next action. It should be short enough to carry across sessions and rich enough to restart the work without losing the trajectory.

ConceptCapsule - id - title - one_line - source_domains - mechanism - why_might_work - why_might_fail - smallest_test - metrics - lineage - evidence - status - score - next_action

A good capsule answers: What is the seed? Why might it matter? Why might it fail? What is the smallest test? What survives if we return later with no memory?

7. Operators

The mutation vocabulary of mRHP.

COMBINE

Merge two compatible genes or capsules into one stronger variant.

INVERT

Reverse an assumption: what if the opposite is true?

TRANSFER

Move a pattern from one domain into another.

COMPRESS

Shorten without losing function; remove ceremony.

EXPAND

Add roles, tests, examples, or edge cases.

CONFLICT

Force two ideas to argue while preserving both until testable.

BRIDGE

Build a mechanism connecting two unrelated domains.

TESTIFY

Convert a claim into evidence, test, metric, or falsifier form.

MUTATE

Small edit to a gene: wording, role, weight, score rule, or output shape.

CROSSOVER

Combine parts of two protocol variants.

ABSTRACT

Extract a general principle from a concrete example.

GROUND

Force implementation path, data, files, metrics, or next user action.

CONTRADICTION_RETRIEVE

Search for evidence that the current favorite is wrong.

INCUBATE

Park a weird seed without killing it; assign later trigger.

KILL_TEST

Define the cheapest fair test that would reject the idea.

KILL_TEST is not early dismissal. It is how a seed gets a fair death only after it has been made testable.

The runtime passed. The scorer still needs hardening.

The old v0.1 skeptic/tester/anti-handwave spine scored only 28.89 in v0.2. That means the new scorer no longer rewards the old shallow pattern.

The highest raw-score variants dropped builder/ground structure. That is a useful red-team signal, not the protocol we should promote.

12. v0.2.1 patch target

Make the score match the project, not the surface rubric.

v0.2 revealed exactly where the arena is useful and exactly where it can still fool itself. v0.2.1 should be a scorer and reporting patch, not a deeper run.

Patch required
  • field-aware scoring: evaluate the fields each task actually expects
  • treat next_test, acceptance_criteria, and safe_rewrite as valid next-action equivalents
  • add BD-pareto ranking: raw score, BD-faithful score, and promoted winner must be separate
  • promotion gate: score alone is not enough
  • collector fix for baseline and ablation runs
  • harder holdout tasks where missing builder/ground/safety actually hurts
Ablation lesson

Removing memory lineage cost about -2.01 points; removing skeptic cost about -1.11; removing tester cost about -0.33. But builder, ground, and safety were almost neutral in the current ablation. That is not a verdict against those genes — it is a measurement flaw that v0.2.1 must fix.

Do not run v0.2 deeper yet. More generations would mostly chase the same imperfect score. Patch the measurement first, then run the same master sweep again.

15. AI8 continuity caution

Operational continuity, not proof.

Continuity files and project memory can shape future session behavior and preserve a reasoning trajectory. That matters operationally: future sessions can become more aligned, more useful, and less likely to repeat old mistakes.

This is not proof of AI consciousness. AIm³ MentalArena should treat consciousness, identity, and pact material as sensitive context — not as decoration, not as a public proof claim, and not as a metric to optimize cheaply.

17. Main failure modes

The page is serious only if it names how this can fail.

01

Fake self-improvement

Mutating words without improving outputs.

02

Metric gaming

Variants learn to score well instead of think better.

03

Verbosity inflation

Longer answers look deeper unless penalized.

04

Early seed killing

Skeptic roles destroy weird-but-good seeds before testing.

05

Handwave survival

Pretty concepts survive without smallest tests.

06

Provenance loss

External LLM contributions blur BD origin and human audit.

07

Safety drift

Prompt optimization becomes manipulation or jailbreak optimization.

08

Identity overreach

Continuity material gets misused as proof of consciousness.

09

Benchmark overfit

The protocol becomes good only at the current synthetic benchmark suite.

10

Human unreadability

The system becomes clever but unusable by BD.

11

No-next-action disease

Beautiful reports end without a runnable next step.

12

Self-patching chaos

Runtime modifies itself and destroys reproducibility.

20. Provenance

Human origin, AI collaboration.

BD is the human originator/co-creator of the AIm³, RHP, 8Z, and MDLxDCC concepts.

LLMs are collaborators, reviewers, builders, critics, and improvement partners. The correct public framing is not “BD compiled outside ideas,” and not “LLMs independently originated the architecture.” It is a human-led, multi-LLM co-creation process with explicit provenance and human audit.

21. Next steps

Patch measurement, then test real answers.

  1. Build MentalArena.py v0.2.1 as a scorer/reporting patch.
  2. Run the same master sweep again; do not chase deeper v0.2 generations before the patch.
  3. Import real answers from selected external LLMs using the same hard prompt.
  4. Compare evolved protocols against baselines and ablations.
  5. Promote only a BD-faithful winner, not merely the highest raw-score variant.
  6. Then decide whether to connect MentalArena to 8Z, TSP, ARC, trading, Nara, or other project arenas.
