Simple meaning

Demon is not a replacement for DCC. DCC remains the controller. Demon is the decision-quality layer that tells DCC which MDL/LZ/process signals deserve trust.

DCC = driver / controller
MDL-LZ = measurement channel
8Z Demon = diagnostic + gate/governor layer

The first Sudoku evidence says the useful pattern is not merely “lower ΔL is better.” It is closer to:

differentiate -> cascade -> compress

The first result does not say “Demon solves Sudoku.” It says: Demon can help DCC select cleaner trajectories by using process-side differentiation and cascade potential.

Mechanism

The original Maxwell-demon intuition was “sort rare useful fluctuations.” The computational version is narrower and testable:

1. generate candidate moves
2. measure state/candidate/process ΔL
3. compare chosen moves against operator-matched random controls
4. test whether ΔL predicts future gain
5. if signal is real, use it as a DCC gate/governor

In Sudoku, process-side ΔL and cascade depth appear more useful than raw board-state compression. That is why v0.4 adds a clean process-cascade gate and a separate event-scout mode.

Claim boundary

8Z Demon does not claim physical thermodynamic proof, perpetual motion, or a literal Maxwell demon. It is a search-level feedback-information diagnostic inspired by stochastic thermodynamics.
