RouteSignal Scout

A read-only internet-ops prototype that helps turn noisy public routing data into a short review queue: where should a human look first if routing starts behaving strangely? It does not claim to prove attacks, hijacks, outages, leaks, or misconfigurations.

Read-only internet-ops prototip, ki pomaga hrupne javne routing podatke pretvoriti v kratek seznam za pregled: kam naj človek najprej pogleda, če se routing začne obnašati čudno? Ne trdi, da dokazano zazna napade, hijacke, izpade, leak-e ali napačne konfiguracije.

Why this mattersZakaj je to pomembno

noisy routing data → smaller human review queue

The simple idea: internet routing is the hidden layer that decides which path data takes between networks. When that layer becomes noisy — prefix churn, flapping, policy shifts, or visibility gaps — people may experience slowdowns, unstable reachability, or strange regional problems. RouteSignal Scout does not fix the internet by itself. Its purpose is to help humans find the small set of routing windows worth investigating first.

Preprosta ideja: internetni routing je skriti sloj, ki odloča, po kateri poti potujejo podatki med omrežji. Ko ta sloj postane šumen — prefix churn, flapping, policy spremembe ali luknje v vidljivosti — lahko uporabniki občutijo upočasnitve, nestabilno dosegljivost ali čudne regionalne težave. RouteSignal Scout interneta ne popravi sam. Njegov namen je pomagati ljudem hitreje najti majhen nabor routing oken, ki jih je smiselno najprej preveriti.

Who it helps

Komu pomaga

The direct users are network operators, NOC/SRE teams, routing researchers, and incident-review teams. Normal internet users would benefit only indirectly: if operators can find routing problems faster, the visible experience can become more stable.

Neposredni uporabniki so omrežni operaterji, NOC/SRE ekipe, routing raziskovalci in ekipe za pregled incidentov. Navadni uporabniki imajo korist posredno: če operaterji hitreje najdejo routing težave, je lahko vidna uporabniška izkušnja bolj stabilna.

What it helps with

Pri čem pomaga

The tool reduces the search space. Instead of staring at thousands of noisy updates and duplicated alerts, a human gets a ranked review queue: this ASN, this prefix, this time window, with this evidence quality and these caveats.

Orodje zmanjša prostor iskanja. Namesto pregledovanja tisočev šumnih update-ov in podvojenih alertov človek dobi razvrščen review queue: ta ASN, ta prefix, to časovno okno, s takšno kakovostjo evidence in s takšnimi omejitvami.

Real-world value

Realna vrednost

The practical value is faster triage, fewer duplicate alerts, better post-mortems, and less wasted expert time. If a real routing problem is found earlier, fixes can happen earlier too — which may reduce the duration of slowdowns, reachability issues, or unstable paths.

Praktična vrednost je hitrejša triaža, manj podvojenih alertov, boljši post-mortemi in manj izgubljenega časa strokovnjakov. Če je realna routing težava najdena prej, se lahko prej tudi popravi — kar lahko skrajša trajanje upočasnitev, težav z dosegljivostjo ali nestabilnih poti.

What this could improve

Kaj bi lahko izboljšalo

RouteSignal is not a bandwidth booster and does not touch routers. But routing problems can indirectly affect speed, latency, stability, and equipment noise. If the tool helps operators detect bad paths, repeated flapping, excessive churn, or policy mistakes sooner, the downstream result can be fewer long slowdowns, quicker recovery, and cleaner operations.

RouteSignal ni pospeševalnik pasovne širine in ne upravlja routerjev. Toda routing težave lahko posredno vplivajo na hitrost, latenco, stabilnost in operativni šum opreme. Če orodje operaterjem pomaga prej opaziti slabe poti, ponavljajoči flapping, pretiran churn ali policy napake, je lahko končni učinek manj dolgih upočasnitev, hitrejše okrevanje in čistejše operacije.

Technical contribution

Tehnični doprinos

Technically, RouteSignal is a read-only BGP/routing review layer. It ranks ASN/prefix/time windows using residual/complexity-style signals, parsed-update evidence, source-quality checks, repeated-resource support, known-event/control comparisons, false-positive pressure, and a global event ledger that merges duplicate alerts.

Tehnično je RouteSignal read-only BGP/routing review sloj. ASN/prefix/časovna okna razvršča z residual/complexity-style signali, parsed-update evidence, source-quality preverjanjem, repeated-resource podporo, known-event/control primerjavami, false-positive pritiskom in global event ledgerjem, ki združuje podvojene alerte.

Safety boundary: RouteSignal does not say “this is an attack,” “this is a hijack,” or “change this route.” It says: “this routing window looks unusual enough to review — here is why.” The output is a review queue, not a verdict.

Varnostna meja: RouteSignal ne reče “to je napad”, “to je hijack” ali “spremeni to routo”. Reče: “to routing okno izgleda dovolj nenavadno za pregled — tukaj je razlog.” Rezultat je review queue, ne razsodba.

What this isKaj je to

seed → bridge → test → current state

Seed

BGP update streams have structure. Stable routing should be comparatively compressible; flapping, churn, policy shifts, or visibility changes can create higher residual and higher complexity.

BGP update streami imajo strukturo. Stabilen routing bi moral biti relativno stisljiv; flapping, churn, policy spremembe ali spremembe vidljivosti lahko ustvarijo višji residual in višjo kompleksnost.

Bridge

Use MDL-style residual/complexity metrics and DCC-style multi-signal gating over public RIPEstat data, with deterministic demo data, offline replay, source-quality warnings, and operator-facing reports.

Uporabi MDL-style residual/complexity metrike in DCC-style multi-signal gating nad javnimi RIPEstat podatki, z determinističnim demo načinom, offline replayem, source-quality opozorili in operaterskimi poročili.

v0.1e proved the long-run evidence harness. v0.2 adds the analyzer/report layer: global event ledger, parsed-first operator report, known-event/control report, false-positive load summary, test bundles, and thinner review packaging.

v0.1e je dokazal long-run evidence harness. v0.2 doda analyzer/report sloj: global event ledger, parsed-first operator report, known-event/control report, false-positive load summary, test bundle in tanjše review pakiranje.

Why this case study matters

Zakaj je ta case study pomemben

RouteSignal became more than a routing prototype: it became a controlled prompt-method test. The same real task — build a Python read-only routing-signal scout — was given through several prompt-building paths, then judged first at prompt level and later by the actual Python packages those prompts produced.

RouteSignal je postal več kot routing prototip: postal je kontroliran test prompting metod. Ista realna naloga — zgraditi Python read-only routing-signal scout — je šla skozi več poti priprave prompta, nato pa je bila ocenjena najprej na ravni promptov in kasneje še po dejanskih Python paketih, ki so iz teh promptov nastali.

This is intentionally a practical engineering case, not a universal benchmark. It asks a narrow but useful question: which workflow recovered the most implementation-critical structure for this difficult coding-builder task?

To je namerno praktičen inženirski primer, ne univerzalni benchmark. Vprašanje je ozko, a uporabno: kateri workflow je za to zahtevno coding-builder nalogo obnovil največ implementacijsko kritične strukture?

Bottom-line interpretation

Glavna interpretacija

The study did not show that Prompt Coach is useless. It showed something more specific: on this difficult RouteSignal coding-builder task, Prompt Coach improved clarity and safety, but produced the weakest builder prompt and the weakest resulting Python package. RHPr/RHP and the BD × GPT hybrid workflow recovered more implementation-critical details: endpoint specificity, data-quality handling, offline fallback, test discipline, MDL×DCC scoring, and operator-review reporting.

Študija ni pokazala, da je Prompt Coach neuporaben. Pokazala je nekaj bolj specifičnega: pri tej zahtevni RouteSignal coding-builder nalogi je Prompt Coach izboljšal jasnost in varnost, vendar ustvaril najšibkejši builder prompt in najšibkejši nastali Python paket. RHPr/RHP in BD × GPT hibridni workflow sta bolje obnovila implementacijsko kritične podrobnosti: endpoint specifiko, data-quality handling, offline fallback, testno disciplino, MDL×DCC scoring in operator-review reporting.

This is why RouteSignal is now useful both as an Internet-ops prototype and as a concrete demonstration of the RHPr/RHP workflow: the method advantage survived the move from prompt scoring to actual code output. Read the full case study.

Zato je RouteSignal zdaj uporaben tako kot Internet-ops prototip kot tudi kot konkreten prikaz RHPr/RHP workflowa: prednost metode je preživela prehod iz ocenjevanja promptov v dejanski rezultat kode. Preberi celoten case study.

What looks promising

Kaj izgleda obetavno

The strongest signal remains prefix-level updates_parsed evidence with repeated independent-signal agreement. v0.2 improves the situation by merging repeated stage/cycle hits into a global event ledger and by promoting parsed-first operator reports.

Najmočnejši signal ostaja prefix-level updates_parsed evidence s ponovljenim neodvisnim signalnim soglasjem. v0.2 izboljša sliko tako, da ponavljajoče stage/cycle zadetke združi v global event ledger in promovira parsed-first operator report.

What is weak

Kaj je šibko

Known-event validation is still mixed: Cloudflare 1.1.1.1 shows weak activity-only lift, Facebook 2021 is unsuitable/missing in the RIPEstat path, and AS13335 2026 did not beat its control in the current evidence.

Known-event validacija je še vedno mešana: Cloudflare 1.1.1.1 pokaže šibek activity-only lift, Facebook 2021 je v RIPEstat poti neuporaben/missing, AS13335 2026 pa v trenutnih dokazih ni premagal kontrole.

Main engineering issue

Glavni inženirski problem

v0.2 solves the old global-ledger/reporting gap, but the deep-live collector still lets some per-stage artifacts grow far beyond the 50 MB target. That is now the main packaging bug.

v0.2 reši star global-ledger/reporting gap, vendar deep-live collector še vedno dovoli, da nekateri per-stage artifacti zrastejo daleč čez 50 MB target. To je zdaj glavni packaging bug.

Main science issue

Glavni raziskovalni problem

Some major-ASN runs are still activity-only dominated. That tells us the ASN path is weaker than the prefix path unless parsed evidence is available, and the ranking gate must enforce that more aggressively.

Nekateri major-ASN teki so še vedno activity-only dominirani. To pomeni, da je ASN pot šibkejša od prefix poti, razen kadar imamo parsed evidence, zato mora ranking gate to strožje uveljaviti.
