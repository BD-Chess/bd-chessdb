RouteSignal Scout

A read-only routing-signal prototype that ranks ASN/prefix/time windows which look structurally unusual and worth operator review — without claiming to detect attacks, hijacks, outages, leaks, or misconfigurations.

Read-only prototip za analizo routing signalov, ki razvršča ASN/prefix/časovna okna, ki so strukturno nenavadna in vredna operaterskega pregleda — brez trditve, da dokazano zazna napade, hijacke, izpade, leak-e ali napačne konfiguracije.

Seed

BGP update streams have structure. Stable routing should be comparatively compressible; flapping, churn, policy shifts, or visibility changes can create higher residual and higher complexity.

BGP update streami imajo strukturo. Stabilen routing bi moral biti relativno stisljiv; flapping, churn, policy spremembe ali spremembe vidljivosti lahko ustvarijo višji residual in višjo kompleksnost.

Bridge

Use MDL-style residual/complexity metrics and DCC-style multi-signal gating over public RIPEstat data, with deterministic demo data and offline replay.

Uporabi MDL-style residual/complexity metrike in DCC-style multi-signal gating nad javnimi RIPEstat podatki, z determinističnim demo načinom in offline replayem.

v0.1e je ustvaril delujoč harness: fetch, cache, resume, replay, scoring, clustering, operator queue, HTML/CSV/JSON reporte in thin extraction.

Why this case study matters

Zakaj je ta case study pomemben

RouteSignal became more than a routing prototype: it became a controlled prompt-method test. The same real task — build a Python read-only routing-signal scout — was given through several prompt-building paths, then judged first at prompt level and later by the actual Python packages those prompts produced.

RouteSignal je postal več kot routing prototip: postal je kontroliran test prompting metod. Ista realna naloga — zgraditi Python read-only routing-signal scout — je šla skozi več poti priprave prompta, nato pa je bila ocenjena najprej na ravni promptov in kasneje še po dejanskih Python paketih, ki so iz teh promptov nastali.

This is intentionally a practical engineering case, not a universal benchmark. It asks a narrow but useful question: which workflow recovered the most implementation-critical structure for this difficult coding-builder task?

To je namerno praktičen inženirski primer, ne univerzalni benchmark. Vprašanje je ozko, a uporabno: kateri workflow je za to zahtevno coding-builder nalogo obnovil največ implementacijsko kritične strukture?

Bottom-line interpretation

Glavna interpretacija

The study did not show that Prompt Coach is useless. It showed something more specific: on this difficult RouteSignal coding-builder task, Prompt Coach improved clarity and safety, but produced the weakest builder prompt and the weakest resulting Python package. RHPr/RHP and the BD × GPT hybrid workflow recovered more implementation-critical details: endpoint specificity, data-quality handling, offline fallback, test discipline, MDL×DCC scoring, and operator-review reporting.

Študija ni pokazala, da je Prompt Coach neuporaben. Pokazala je nekaj bolj specifičnega: pri tej zahtevni RouteSignal coding-builder nalogi je Prompt Coach izboljšal jasnost in varnost, vendar ustvaril najšibkejši builder prompt in najšibkejši nastali Python paket. RHPr/RHP in BD × GPT hibridni workflow sta bolje obnovila implementacijsko kritične podrobnosti: endpoint specifiko, data-quality handling, offline fallback, testno disciplino, MDL×DCC scoring in operator-review reporting.

This is why RouteSignal is now useful both as an Internet-ops prototype and as a concrete demonstration of the RHPr/RHP workflow: the method advantage survived the move from prompt scoring to actual code output. Read the full case study.

Zato je RouteSignal zdaj uporaben tako kot Internet-ops prototip kot tudi kot konkreten prikaz RHPr/RHP workflowa: prednost metode je preživela prehod iz ocenjevanja promptov v dejanski rezultat kode. Preberi celoten case study.

What RouteSignal scores

Kaj RouteSignal ocenjuje

  • Volume residual against the resource’s own baseline.
  • Symbolic complexity / diversity proxies.
  • Withdrawal and burst behavior.
  • Peer contrast when comparable peer resources exist.
  • Source-quality and data-quality warnings.
  • Volume residual glede na lastni baseline resursa.
  • Symbolic complexity / diversity proxy signale.
  • Withdrawal in burst obnašanje.
  • Peer contrast, kadar obstajajo primerljivi peer resursi.
  • Source-quality in data-quality opozorila.

What it does not claim

Česa ne trdi

A high score means “routing-signal candidate worth operator review.” It does not mean proven incident, attack, hijack, route leak, outage, or misconfiguration.

Visok score pomeni “routing-signal kandidat vreden operaterskega pregleda.” Ne pomeni dokazan incident, napad, hijack, route leak, izpad ali napačna konfiguracija.

What looks promising

Kaj izgleda obetavno

The strongest signal is not generic ASN activity. It is prefix-level updates_parsed evidence with repeated independent-signal agreement: volume, complexity, diversity, peer contrast, and sometimes IP-version signal.

Najmočnejši signal ni generična ASN aktivnost. Najmočnejši so prefix-level updates_parsed dokazi s ponovljenim neodvisnim signalnim soglasjem: volume, complexity, diversity, peer contrast in včasih IP-version signal.

What is weak

Kaj je šibko

Known-event validation is mixed: Cloudflare 1.1.1.1 shows only weak activity-only lift, Facebook 2021 has missing/partial data, and AS13335 2026 did not beat its control in the current v0.1e evidence.

Known-event validacija je mešana: Cloudflare 1.1.1.1 pokaže le šibek activity-only lift, Facebook 2021 ima missing/partial podatke, AS13335 2026 pa v trenutnih v0.1e dokazih ni premagal kontrole.

Main engineering issue

Glavni inženirski problem

There is still too much repetition across stages/cycles. The next analyzer must merge the same resource/time/signal into a global event ledger.

Še vedno je preveč ponavljanja čez stage/cycle teke. Naslednji analyzer mora isti resource/time/signal združiti v global event ledger.

Main science issue

Glavni raziskovalni problem

RouteSignal currently detects unusual routing structure. It does not yet explain which BGP mechanism caused it. v0.2 should make this boundary explicit.

RouteSignal trenutno zaznava nenavadno routing strukturo. Še ne razloži, kateri BGP mehanizem jo je povzročil. v0.2 mora to mejo jasno zapisati.
