Preparation / Genesis Plane

AI8 currently selects what to investigate and which mechanisms to use. This branch makes another object explicit and testable: how a fresh worker—or a temporary research team—is prepared before research begins.

What changes

verified AI8 state / task contract ↓ Preparation Compiler / Team Architect ↓ frozen, audited preparation artifact ↓ fresh isolated worker(s) ↓ OUTER / INNER research and cheapest differentiating tests ↓ Arena result + cost + leakage audit ↓ META learns which preparation policy is worth using
Important: this is a Preparation / Genesis plane, not a fourth top-level loop. It spans AIM³/RHP, OUTER and META.

Modes

D0

Prepared Single · General

Parent prepares a researcher before task identity is revealed.

D1

Prepared Single · Task-aware

Parent knows the task but remains solution-blind and cannot access hidden truth.

D2

AI-Prepared Research Team

Parent creates a functionally diverse temporary team with distinct preparation, sealed independent work, controlled cross-review, preserved tensions and explicit synthesis.

What v0.4.1 hardened

Immutable run chain

Contract → task commitment → runtime environment → blueprint/capsules → sealed Round 1 → cross-review → synthesis → test → result → cost → blind evaluation → run record.

Fresh-worker boundary

Model/build, system prompt hash, sampling, tools and absence of memory/project/prior-chat context are recorded.

Causal decomposition

Preparation, diversity and coordination are separated. P2_MATCHED gives the same prepared workers comparable extra compute without communication.

Team-only emergence

CROSS_MEMBER_BRIDGE requires hashed Round-1 claim lineage and independent semantic adjudication before promotion.

Cost ledger

Architect, preparation, workers, review, synthesis, evaluator, tools and human attention are counted.

Fail-closed controls

Leakage, broken seals, duplicate member IDs, unsupported bridges and budget mismatch must fail rather than silently pass.

Why this matters for Bounded-Ridge

A prepared worker may merely reach a better point on the same abstraction ridge—or may become more likely to challenge and rebuild the representation. D2 adds a second hypothesis: differently prepared workers may cover different ridges and create a valid bridge only after controlled interaction.

No solution is assumed. If Prepared Single, Prepared Team and Team Genesis fail matched held-out representation-shift tests, the Bounded-Ridge objection survives.

Public claim boundary

This page documents an experiment-ready candidate mechanism, not a validated capability. It does not establish AI self-improvement, team superiority, autonomous representation invention, AGI, consciousness, or a CLV result.

The canonical CLV v0.4.2 documents remain unchanged. Preparation / Genesis is linked here because it may become a useful experimental instrument for testing representation reopening and worker/team configuration under matched budgets.

Promotion boundary

Current status: experiment-ready, not evidence-backed.

Promotion into an ArenaLoop candidate architecture should require replicated, cost-adjusted downstream gain and independently adjudicated team-only bridge evidence on more than one held-out task family. Until then, Architecture Spec v0.2.2 remains immutable.
