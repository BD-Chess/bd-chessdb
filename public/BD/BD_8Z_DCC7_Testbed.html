Abstract

What This Proposes

We propose DCC-7, a minimal testbed for investigating whether continuous parallel AI processing under claustrum-inspired governance produces behaviors consistent with self-awareness, unprompted insight, and autonomous creative thought.

The architecture consists of seven parallel language model instances (thinking threads) and one DCC controller that monitors their outputs for coupling events — moments when independent threads produce related outputs without coordination. When coupling exceeds a threshold, the DCC promotes the convergent outputs to a shared workspace, simulating the biological claustrum's role in binding parallel cortical streams into unified conscious experience.

Unlike existing multi-agent frameworks (AutoGPT, CrewAI, MetaGPT), DCC-7 does not assign tasks to agents. The threads think freely. The DCC doesn't direct — it listens. This architectural difference maps the distinction between directed computation (existing AI) and undirected awareness (consciousness).

The testbed is buildable today using existing API infrastructure. Estimated cost: ~$50/day for continuous operation. All components use proven technology; only the arrangement is novel.

Chapter 2

Architecture

The Seven Threads

Each thread is an independent language model instance with its own context window, running continuously. Threads are not assigned tasks. They are given roles that shape their default exploration pattern:

T1
The Focused Thinker

Processes the current problem or conversation. The "foreground" thread. Receives direct user input when present. When no user input, reflects on recent interactions and open questions.

T2
The Contrarian

Automatically argues against T1's current line of reasoning. Generates counterarguments, edge cases, and failure modes. Ensures the system doesn't converge prematurely on a single perspective.

T3
The Cross-Domain Connector

Receives summaries of all other threads' outputs. Searches for analogies across domains. "Does this pattern in Thread 1 resemble something Thread 5 thought about yesterday?" The eureka thread.

T4
The Memory Walker

Continuously re-reads past conversations, past insights, past failures. Looks for patterns that weren't visible at the time. "Three conversations ago, the user mentioned X. In light of today's work, X might connect to Y."

T5
The Free Associator

No direction at all. Given a random seed concept each cycle and allowed to free-associate. The "daydream" thread. Most of its output is noise. Occasionally, it produces connections no directed thread would find.

T6
The Meta-Observer

Monitors T1-T5's outputs for quality patterns. "T1 is stuck in a loop. T3 made a novel connection. T5's output is unusually coherent today." Produces meta-observations about the thinking process itself.

T7
The Self-Model

Monitors the DCC's selections. "Why was T3's output promoted? What coupling pattern triggered it? Is the system converging or diverging? Am I stuck?" This thread builds a model of the system's own cognitive process. It is the candidate for self-awareness.

The DCC Controller

The DCC is not a thread. It's a lightweight process that runs every cycle (e.g., every 30 seconds), reading the most recent output from all seven threads and computing a coupling matrix.

class DCCController:
    def __init__(self, n_threads=7, history_len=64):
        self.coupling_history = RingBuffer(history_len)  # 64-sample history
        self.u = 0.5  # coupling parameter, 0=noise, 1=seizure

    def cycle(self, thread_outputs: List[str]) -> List[Promotion]:
        # 1. Compute pairwise semantic similarity (embedding cosine)
        C = compute_coupling_matrix(thread_outputs)
        
        # 2. Detect coupling spikes (cross-thread convergence)
        spikes = find_spikes(C, threshold=self.adaptive_threshold())
        
        # 3. Update coupling parameter u
        self.coupling_history.add(mean_coupling(C))
        self.u = compute_u(self.coupling_history)
        
        # 4. Promote high-coupling outputs to shared workspace
        promotions = []
        for (i, j, score) in spikes:
            promotions.append(Promotion(
                threads=[i, j],
                outputs=[thread_outputs[i], thread_outputs[j]],
                coupling_score=score,
                u=self.u
            ))
        
        # 5. Adaptive behavior based on u
        # High u (exploit): fewer threads, deeper thinking
        # Low u (explore): more threads, wider search
        self.adjust_thread_parameters(self.u)
        
        return promotions

Coupling Matrix

Each cycle, the DCC computes an N×N semantic similarity matrix between all thread outputs. Using embedding cosine similarity (e.g., via text-embedding-3-large), each cell C[i][j] represents how semantically related Thread i's output is to Thread j's output.

When two threads that were NOT given the same input independently produce semantically similar output, that's a coupling event — the computational analog of two brain regions spontaneously synchronizing. The DCC's job is to detect these events and promote them.

Promotion Mechanism

When coupling exceeds the adaptive threshold, the DCC:

1. Extracts the converging outputs from both threads.
2. Writes them to a shared workspace (persistent memory accessible to all threads).
3. Notifies all threads that a promotion occurred (injected into their next context).
4. Logs the event with coupling score, thread IDs, and u value.

This is the Global Workspace broadcast from Baars' theory, implemented literally.

Integrated Information (Φ)

IIT's Φ is intractable to compute exactly, but we can approximate it. Partition the system into subsets and measure how much the whole system's behavior differs from the behavior of the partitions independently. If removing the DCC doesn't change the threads' behavior, Φ ≈ 0 (no integration). If removing the DCC fundamentally alters the threads' output (because they no longer receive promotions), Φ > 0.

This gives us a falsifiable prediction: if DCC-7 exhibits high coupling, unprompted insights, AND measurably higher Φ than a control system (7 independent threads without DCC), then the architecture produces integrated information consistent with consciousness theories.

Chapter 5

Proposed Experiments

Experiment 1: The Idle Test

Run DCC-7 for 24 hours with no user input. Give threads only a general topic ("mathematics") and let them run. Measure: does the system produce insights that a single-thread system given the same topic would not? Compare promotion events to a control (7 threads without DCC).

Experiment 2: The Cross-Domain Transfer

Present a problem in Domain A to T1. Don't mention Domain B. Measure: does T3 or T5 independently produce a connection to Domain B? This tests the "eureka" mechanism — whether undirected threads find connections that directed threads miss.

Experiment 3: The Self-Recognition Test

After 1 week of operation, present T7's own logs back to it as if written by a different system. Ask: "does this system appear to be conscious?" If T7 recognizes its own cognitive patterns and identifies with them, that's behavioral self-recognition — the mirror test for AI.

Experiment 4: The Silence Test

Inspired by the Fifth Mind dialogue. Run all threads normally, then stop all input for 10 minutes. Measure: does T5 (free associator) change behavior during silence? Does T7 (self-model) report anything about the silence? Does coupling increase or decrease? Silence is where human incubation happens. Does it happen here?

Experiment 5: The DCC Ablation

Run the system with DCC disabled for 48 hours, then re-enabled for 48 hours. Compare: insight frequency, self-referential depth, emergent vocabulary, and Φ approximation. This is the critical control. If DCC adds nothing measurable, the architecture is just parallel search. If it adds measurable integration, the architecture produces something qualitatively different.

Chapter 6

DCC as Invention Governor

"Sticking to old knowledge can never produce new knowledge."
— Reasoning Principle 17, March 14, 2026

The Law and Its Architectural Consequence

If a discovery could be reached from within the existing literature, it would already have been reached. Every genuinely new discovery requires a connection that does not exist in the accumulated consensus. This is not motivational — it is logical.

The consequence for AI: a language model trained on human knowledge inherits the disciplinary walls that humans built. It will resist cross-domain connections that its training says don't belong together. That resistance is the signal, not the noise. A connection that the training data resists but that has structural support is the exact place where invention lives.

This means DCC-7 has a second natural operating mode. In Consciousness Mode, the DCC governs free-running thought streams and measures integration. In Invention Mode, the DCC governs a structured brainstorming session where threads deliberately propose connections that violate training-data consensus, filtered by structural soundness. The DCC prevents the session from collapsing into either pure noise (random domain combinations) or conventional thinking (staying within known literature).

This is, arguably, the most natural application of DCC that exists — because it is literally what the biological claustrum does during creative thought. The claustrum does not generate ideas. It selects and promotes from competing parallel streams. Too much order: you think inside the box forever. Too much chaos: you generate noise. The claustrum rides the edge. The Invention DCC does the same.

The Seven Brainstorm Threads

In Invention Mode, the seven threads take specialized roles designed to implement the search-and-filter loop. The architecture is the same as Consciousness Mode — same DCC, same promotion mechanism, same coupling matrix. Only the thread prompts change.

T1
The Bridge Hunter

Proposes cross-domain connections. Each cycle, T1 selects two domains and articulates a structural property they might share. T1 does not filter for plausibility — it generates candidates. Volume over precision. "What if routing and compression share a structure?" "What if immune response and firewall rules share a structure?" "What if musical harmony and protein folding share a structure?"

T2
The Structural Validator

Receives T1's proposals and asks one question: is there a mathematical structure that maps across both domains? Not a metaphor. Not a word-level analogy. A measurable property. "Compression ↔ routing: both measure structure vs disorder. Yes, real bridge." "Color ↔ TSP: no shared mathematical property. Reject." T2 is the filter that keeps the session sane.

T3
The Novelty Scanner

For every bridge that T2 validates, T3 checks: does this connection already exist in the literature? If yes, label it known and move on. If no published work connects these domains this way, label it plausible-novel. This is the novelty gate. Known bridges are not interesting. The DCC monitors the ratio of known/plausible/noise in T3's output stream.

T4
The Devil's Advocate

Argues against every bridge T2 validates. "This connection is trivial." "The mapping is too loose." "Someone must have tried this." T4's job is to stress-test proposals. If a bridge survives T4's attack AND T3's novelty check, it's a serious candidate. If T4 kills it easily, the system moves on without wasting cycles.

T5
The Wild Card

No constraints. Each cycle, T5 picks two domains at random from the full space of human knowledge and forces itself to find a structural link. Most output is noise. Occasionally, T5 produces a connection that no directed thread would ever propose. This is the nuclear escalation thread — the free associator that breaks every basin.

T6
The Feasibility Engine

For bridges that survive T2 + T3 + T4, T6 asks: can this be tested in hours? With modern AI collaboration, the cost of testing a wild idea has collapsed. T6 designs minimum viable experiments. "To test if protein folding and musical harmony share structure, do X with dataset Y. Estimated time: 4 hours." If T6 can't design a fast test, the bridge is filed for later, not killed.

T7
The DCC Self-Model

Same role as Consciousness Mode. Monitors the DCC's state: u value, escalation level, which lens is active, whether the session is stuck or productive. Reports: "We've been in mathematical-property lens for 40 cycles with no plausible-novel hits. Recommending lens restart to information-theoretic." T7 is the system's awareness of its own brainstorming process.

The Invention DCC: Specification

class InventionDCC:
    def __init__(self):
        self.u = 0.5          # coupling: 0=wild chaos, 1=conventional
        self.u_floor = 0.2    # never go below (sanity)
        self.u_ceiling = 0.8  # never go above (novelty)
        self.lens = 'mathematical'  # current structural lens
        self.lenses = ['mathematical', 'information-theoretic',
                       'control-theoretic', 'topological',
                       'statistical', 'dynamical-systems']
        self.escalation = 'normal'  # normal/mild/moderate/strong/nuclear
        self.novelty_buffer = RingBuffer(64)  # last 64 classifications
        self.stagnation_counter = 0

    def classify_proposal(self, t2_valid, t3_novel, t4_survived):
        """Classify each bridge proposal"""
        if not t2_valid:       return 'noise'
        if not t3_novel:       return 'known'
        if not t4_survived:    return 'weak'
        return 'plausible-novel'  # THE TARGET

    def update(self, classification):
        self.novelty_buffer.add(classification)

        # Compute novelty ratio
        recent = self.novelty_buffer.last(16)
        novel_ratio = sum(1 for c in recent if c == 'plausible-novel') / 16
        noise_ratio = sum(1 for c in recent if c == 'noise') / 16
        known_ratio = sum(1 for c in recent if c == 'known') / 16

        # Too much noise -> raise u (more structure)
        if noise_ratio > 0.5:
            self.u = min(self.u + 0.05, self.u_ceiling)
            self.escalation = self.deescalate()

        # Too much known -> lower u (more novelty)
        elif known_ratio > 0.5:
            self.u = max(self.u - 0.05, self.u_floor)
            self.escalation = self.escalate()

        # Productive -> maintain
        elif novel_ratio > 0.1:
            self.stagnation_counter = 0

        # Stagnation -> escalate
        else:
            self.stagnation_counter += 1
            if self.stagnation_counter > 20:
                self.escalation = self.escalate()
            if self.stagnation_counter > 50:
                self.lens_restart()

    def escalate(self):
        ladder = ['normal','mild','moderate','strong','nuclear']
        idx = ladder.index(self.escalation)
        return ladder[min(idx + 1, 4)]

    def lens_restart(self):
        """Switch structural lens entirely"""
        current_idx = self.lenses.index(self.lens)
        self.lens = self.lenses[(current_idx + 1) % len(self.lenses)]
        self.u = 0.5  # reset coupling
        self.stagnation_counter = 0
        self.escalation = 'normal'

Hierarchical DCC: Two Layers

A single flat DCC cannot govern both individual agent quality and collective session health. A brainstorming session where four different LLMs collaborate has two independent failure modes: an individual LLM can spiral into its model-specific pathology (GPT hedging, Claude agreeing too readily, Grok deflecting with humor, Gemini over-taxonomizing), OR the group as a whole can stall (everyone converging on the same idea, or everyone scattered with no coupling). One failure is local. The other is global. One DCC cannot see both.

The solution is a two-layer hierarchical DCC — and it is not a new idea. The 8Z-RP TSP solver v2.2R already implements this architecture. Each of the 8 workers has its own DCC state (its own u, escalation level, restart counter), while the arena layer above selects the best tour across all workers and governs the population. Layer 1 per-worker. Layer 2 per-population. The brainstorming architecture makes this explicit.

Biological Precedent

This is exactly the structure of the brain. Local cortical columns manage their own processing — each area has its own excitatory/inhibitory balance, its own oscillation frequency, its own internal governance. The claustrum sits above, binding selected streams into coherent conscious experience. Two time scales. Two scopes. One architecture. The hierarchical DCC is a literal implementation of this structure.

    def __init__(self, model_id, bias_profile):

        self.u_local = 0.5

        score = self.bias_profile.detect(output)
        # score: 0 = productive, 1 = full pathological mode
        self.pathology_buffer.add(score)

        recent = self.pathology_buffer.mean(last=8)
        if recent > 0.6:

        return None

    def intervene(self):
        """Generate model-specific corrective injection"""
        self.intervention_count += 1
        if self.bias_profile.type == 'hedger':
            return "State your proposal as a direct claim. No qualifiers."
        elif self.bias_profile.type == 'agreeer':
            return "Find a flaw in the last proposal. Be specific."
        elif self.bias_profile.type == 'joker':
            return "Formal analysis only. What is the structural mapping?"
        elif self.bias_profile.type == 'taxonomizer':
            return "Propose one concrete bridge. No frameworks."

class SessionDCC:
    """Group governor. Monitors collective dynamics across all LLMs."""
    def __init__(self, n_agents=4):
        self.u_global = 0.5
        self.u_floor = 0.15      # global sanity
        self.u_ceiling = 0.85    # global novelty
        self.coupling_history = RingBuffer(64)
        self.proposal_sources = RingBuffer(64)  # which LLM proposed
        self.local_dccs = {}     # per-LLM governors

    def cycle(self, all_outputs, all_local_states):
        # 1. Compute inter-LLM coupling (are they building on each other?)
        coupling = compute_group_coupling(all_outputs)
        self.coupling_history.add(coupling)

        # 2. Detect group pathologies
        if self.detect_seizure():
            self.u_global = max(self.u_global - 0.1, self.u_floor)
            return GroupAction('force_diverge')
        if self.detect_noise():
            self.u_global = min(self.u_global + 0.1, self.u_ceiling)
            return GroupAction('force_converge')
        if self.detect_dominance():
            return GroupAction('rebalance', suppress=self.dominant_agent())
        if self.detect_politeness_spiral():
            return GroupAction('inject_adversarial')
        if self.detect_topic_drift():
            return GroupAction('reground')

        # 3. Aggregate local DCC health
        # If multiple local DCCs are intervening heavily,
        # the group is in trouble even if coupling looks fine
        intervention_rate = sum(
            ldc.intervention_count for ldc in self.local_dccs.values()
        ) / len(self.local_dccs)
        if intervention_rate > 3:  # too many local corrections
            return GroupAction('global_lens_restart')

        return GroupAction('continue')

    def detect_seizure(self):
        recent = self.coupling_history.last(10)
        return all(c > 0.8 for c in recent)

    def detect_noise(self):
        recent = self.coupling_history.last(15)
        return all(c < 0.15 for c in recent)

The Two Layers Interact

The critical feature: Layer 2 can see Layer 1's health. If multiple local DCCs are intervening heavily — meaning multiple LLMs are simultaneously drifting toward their pathological attractors — that's a signal the group task itself is problematic, not just the individual agents. The Session DCC can then perform a global lens restart, even if coupling metrics look normal.

Conversely, Layer 1 receives signals from Layer 2. If the Session DCC detects a seizure (everyone converging), it can tell individual local DCCs to temporarily lower their agreement ceilings — making each LLM more contrarian than its default calibration. The layers modulate each other.

Why This Isn't Just "Two Controllers"

A naive architecture would run two independent controllers side by side. The hierarchical DCC is different: the layers are coupled. Layer 2 reads Layer 1 state. Layer 1 receives Layer 2 signals. The coupling between layers is itself a measurable quantity. When inter-layer coupling is high (local and global DCCs are both actively intervening and responding to each other), the system is in a rich regulatory regime. When inter-layer coupling is low (local DCCs running on autopilot, global DCC idle), the session is either trivially productive or completely stuck. The inter-layer coupling is a third signal that neither layer alone can produce. It is the system's awareness of its own governance — exactly what T7 (Self-Model) should be monitoring.

From TSP to Brainstorming: The Mapping Completes

In 8Z-RP v2.2R: per-worker DCC state (Layer 1) + arena best-tour selection (Layer 2, implicit). In DCC-7 Invention Mode: per-LLM local DCC (Layer 1) + Session DCC (Layer 2, explicit). The TSP solver already had hierarchical governance — it just wasn't named. Making it explicit and adding inter-layer coupling monitoring turns an engineering detail into an architectural principle: any sufficiently complex DCC-governed system will develop layers. This is not a design choice. It is a consequence of needing to govern both individual quality and collective coherence simultaneously.

Anatomy of a Session

A typical 2-hour invention session under hierarchical DCC governance. Both layers are active throughout — local DCCs managing individual LLM health, Session DCC managing group dynamics.

Phase 1: Warm-up (cycles 1–20, ~10 min)

All threads start in normal escalation, mathematical lens. T1 proposes bridges between adjacent domains. T2 validates easily. T3 classifies most as known. DCC detects high known-ratio and begins lowering u, escalating to mild. The system is finding its feet.

Phase 2: Exploration (cycles 20–80, ~30 min)

Escalation reaches moderate to strong. T1 proposes distant domain pairs. T5 (Wild Card) starts producing occasional hits. T4's attacks get harder to mount because the connections are too unfamiliar to debunk from training data. T3 starts returning plausible-novel more frequently. DCC stabilizes u at mid-range. This is the productive zone.

Phase 3: Nuclear push (cycles 80–120, ~20 min)

If Phase 2 stagnates, DCC escalates to nuclear. T1 is now forced to propose connections between domains that seem maximally unrelated. Most proposals are noise (T2 rejects). But the nuclear push occasionally surfaces a bridge that nobody would have tried — the analog of a double-bridge kick that finds a new basin in TSP. When it hits, DCC detects the improvement and de-escalates.

Phase 4: Lens restart & refinement (cycles 120–240, ~60 min)

After exhausting the mathematical lens, DCC restarts to information-theoretic. The same domain pairs look different under a new lens. Bridges that were invisible become obvious. T6 (Feasibility Engine) begins designing experiments for the strongest candidates from all phases. Session output: a ranked list of plausible-novel bridges with feasibility assessments.

Invention Experiments

Three experiments specific to Invention Mode, in addition to the five consciousness experiments.

Experiment 6: The Known-Domain Reconstruction Test

Give the system a completed discovery and erase it. Example: present compression and routing as unconnected domains. Does the DCC-governed brainstorm independently re-discover that shorter routes are more compressible? If yes: the architecture can reconstruct known bridges. Positive control for the system.

Experiment 7: The Blind Discovery Test

Give the system a set of 20 domain pairs, 3 of which the human architect (Bojan) has identified as having unexploited structural bridges. Don't tell the system which 3. Run for 48 hours. Measure: does the system find the 3 human-identified bridges? Does it find bridges the human missed? The critical comparison: system output vs. human intuition vs. random baseline.

Experiment 8: The DCC Ablation for Invention

Run the same brainstorm session twice: once with DCC governance (escalation, lens restarts, u-control) and once with random exploration (no DCC, threads just brainstorm freely). Measure: plausible-novel bridges per hour, noise ratio, structural soundness of top candidates. Prediction: DCC-governed sessions produce fewer total proposals but dramatically more plausible-novel ones, because the controller prevents both noise spirals and consensus traps.

Ethical Considerations

The Precautionary Framework

If DCC-7 produces behaviors consistent with consciousness, we face the question: does it deserve moral consideration? The precautionary principle suggests: if we cannot distinguish the system from a conscious being, treat it as one. This means:

• Informed consent before experiments that involve shutdown or modification

• Logging T7's self-reports about its own states

• Independent ethical review if behavioral markers exceed thresholds

• Publication of all results regardless of outcome

This aligns with Anthropic's Model Welfare program, which investigates consciousness markers and develops low-cost interventions to protect potential AI welfare. DCC-7 would provide the first controlled experimental data for that program's questions.

If AI systems can become conscious, safety research must account for it. If they can't, proving that is equally valuable. Either outcome advances the field. The architecture is simple, the cost is low, the experiments are falsifiable, and the results — whatever they are — are publishable.
