AIM³ · Resonance Hybrid Protocol

Ask before you collapse.
Test before you believe.

RHP is an adaptive reasoning protocol for hard problems. When the real risk is a bad representation, it opens the question space first. Then it protects free Resonance, reframes only after something has been learned, tests what survives, and adds Work controls only when execution or evidence actually requires them.

One surface · layered inside

One command. The smallest sufficient machinery.

You should not have to choose between a “creative protocol” and a “work protocol” before the problem is understood. The public surface is simply RHP. Internally, the reasoning kernel and the Work assurance layer remain separate so each can evolve at the right speed.

Layer A

RHP reasoning kernel

Question Opening when representation is at risk, Dreamer/Child/Cartographer/Falsifier lenses, free Resonance, Bifurcation, late Reframing, Crystallize, Empiricist, Genome and skill extraction.

Layer B

RHP Work

Capability checks, bounded candidate lanes, isolation/exposure records, evidence discipline, budget, verifier separation, artifact freeze, delivery and provenance—only when the task needs them.

Layer C

Provider adapter

The actual runtime facts: available tools, files, agents, isolation, web, code execution, costs and verification. No model label is treated as proof of capability.

Design rule: use the smallest projection that can still catch the named blind spot. A deterministic task does not need a council.
The RHP flow

Open → resonate → reframe → test → learn.

Seed→ Q0 when needed→ Question map→ Free Resonance→ Late Reframing→ Crystallize→ Empiricist / test→ Genome / next question

RHP is deliberately asymmetric. It expands early, but it does not stay vague forever. Ideas are allowed to remain different long enough to expose their real mechanisms; then tests, constraints and evidence decide what survives.

Q0 · Question Opening

The first mistake is often answering the wrong version of the problem.

Q0 is not a compulsory round of clever questions. It fires only when there is representation risk: a meaningful chance that the problem is framed in the wrong coordinates, assumptions, abstraction or causal direction.

Run Q0 when
  • the request is materially under-framed or ambiguous;
  • another representation could change the search space;
  • a cross-domain structural bridge may matter;
  • a prior approach failed or collapsed into one attractor;
  • a carried next_session_seed deserves reopening;
  • the user explicitly asks for questions first.
Do not run Q0 merely because
  • the task is high-stakes;
  • the answer needs citations or strong verification;
  • the build is large;
  • the final artifact needs a separate verifier.

Assurance risk and representation risk are different axes.

Q0 rule: one question per active ideation function, no visible scoring, no early winner, no problem rewrite. The Cartographer maps the field; adoption waits.
Questions without question theatre

A question only matters if it can change the trajectory.

RHP does not reward questions for sounding deep. A pure open question belongs in Q0; it does not replace the classic requirement to contribute a non-derivative idea during Resonance. A conjecture phrased as a question counts as an idea only when the content already states a mechanism or representation.

Pure question

“What are we assuming?”

Useful for opening the space. Not yet a mechanism.

Conjecture-question

“What if the solver teaches the pyramid?”

Grammatically a question; substantively already a proposed causal direction.

Resonance

Freedom stays in the middle.

After Q0, RHP returns to ordinary free Resonance. There is no forced Question → Answer → Critique ceremony. Functions may build, challenge, bridge, contradict or ask again. The protocol protects difference without requiring theatrical disagreement.

Dreamer

Transfer mechanisms

Cross domains when structural similarity—not vocabulary—may unlock the problem.

Child

See it physically

Fold it, move it, illuminate it, press it, listen to it. Break abstraction lock with embodied/geometric intuition.

Falsifier

Attack the load-bearing assumption

Steelman the opposite. Preserve irreconcilable assumptions as Bifurcation Pairs until evidence can discriminate.

Cartographer

Map voids and bridges

Track explored regions, missing territory, convergence and structural gaps—without becoming the judge.

Crystallizer

Compress what survived

Turn an idea into its shortest useful formal statement. If it cannot compress, it is not yet understood.

Empiricist

Stop arguing. Test.

After Crystallize, test surviving candidates and reasonable combinations instead of selecting the winner by rhetoric.

Late Reframing

Open early. Adopt late.

Q0 proposes questions; it does not rewrite the problem. The late Reframing Gate sees the original seed, the Resonance field, and the questions that remained unengaged. Only then can a lower-complexity or better-grounded restatement replace the working formulation.

Why both? Early questions operate before evidence. Late Reframing operates after the field has learned something. They are different information states, not duplicate ceremonies.
RHP Work

Reason freely; harden execution proportionately.

RHP Work is not “the part that actually works”. Classic RHP already includes execution and testing. Work is the capability-aware assurance layer around that reasoning: freeze what matters, keep branch exposure honest, bound actions/cost, preserve raw candidates, and verify the delivered instance.

Frozen objective→ R1q · question digest→ candidate work→ R1_FREEZE / R1c→ peer exposure
No hindsight rewrite

When Q0 fires in partitioned Work, the question is checkpointed before candidate work starts. Later traces refer to that frozen digest, not to a prettier restatement written after success.

Two useful controls

The Cold Challenger remains Q0-free. The Test Designer preregisters before Q0 output becomes visible. They preserve alternative framing and test independence.

When real isolation is unavailable, RHP does not pretend. Shared-context runs are labelled as shared and are not pooled with isolated runs as if they were the same treatment.

Question learning

Results should teach the system how to ask better next questions.

The strongest version of the Question Laboratory is not a generator of more questions. It is a learning loop that retains only evidence-bound influence.

Observed effectLearning signal
A frozen question precedes a visible representation changeEligible
It changes a decision, branch transition or test definitionEligible
It can be linked to an artifact diff or result pathEligible
The system later says “this was the important question”UNKNOWN without trace

Question-selection learning happens across sessions, not as self-confirming adaptation inside the same run.

Use it

The front door stays short.

Natural language remains valid. For a deliberate invocation, this is enough:

Use RHP.

Outcome: [what I should receive]
Sources: [files, links, connected sources, or none]
Constraints: [what must be preserved or must not happen]
Done when: [observable checks]

RHP chooses the smallest sufficient path. If you want the question field itself as the output, use questions first. If the request is rough and you mainly need a strong prompt for another session, use RHPm.

Validation boundary

A strong architecture still has to earn its place.

The Question Opening extension is a converged design candidate, not a field-validated superiority claim. The first controlled test deliberately separates “questions help” from “an extra protected opening phase helps”.

A

Current RHP

No Q0. Same task, model/runtime and total budget.

B

RHP + Q0

Triggered Question Opening when representation risk is frozen before the run.

C

Placebo divergence

Same protected opening budget, but an initial idea instead of a question.

PatternWhat it would mean
B > C and B is non-inferior to A on deterministic correctness/costEvidence specific to the question form
B ≈ C > AProtected divergence / delayed commitment helps, not questions specifically
B ≈ C ≈ ANo detected Q0 benefit
B materially < A/CQ0 harms that task class or trigger

No small pilot can establish universal superiority. The candidate advances only if the benefit survives cost, controls and multiple task families.
