Why this page exists

AIM³ is the OS. RHPr opens the right drawers. RHP coordinates perspectives. RHPm is the front door: it helps a human convert “make me X” into a session prompt that tells the next model what to inspect, what to preserve, what to build, how to check itself, and when to escalate.

Use RHPm when the prompt is still rough

Use RHPm

For rough requests, file-editing briefs, coding-builder prompts, review prompts, research seeds, HTML pages, and repeatable workflows that need a stronger new-session prompt.

Escalate to RHPr

When the model may be trapped in the wrong knowledge drawer: old assumptions, retrieval bias, messy context, unclear prior files, or “it keeps answering the wrong question.”

Escalate to RHP

When the actual problem needs multi-lens ideation: architecture, theory, strategy, cross-domain synthesis, hard tradeoffs, or high-stakes brainstorming.

Do not use it for everything

If the request is already precise and simple, answer it directly. RHPm earns its overhead when ambiguity, files, constraints, repeated work, or verification matter.

The compact RHPm protocol

00

Guide mode

If the rough request is clear, build the improved prompt directly. If key information is missing, ask up to five practical questions first: deliverable, audience, files/context, constraints, checks, and output format.

01

Protocol choice

Stay with RHPm by default. Recommend RHPr for retrieval-bias / wrong-drawer problems. Recommend RHP for multi-lens brainstorming or architecture. Ask one short question only when the choice materially changes the prompt.

02

Intent split

Extract the explicit request, implied goal, real deliverable, audience, context to inspect, constraints, and “what good looks like.”

03

Mini-RHP lens pass

Use five practical RHP lenses: EngineerFalsifierChildCartographerAgent 0. Each lens must improve the final prompt, not produce ceremonial commentary.

04

Resonance guard

Detect seizure when the prompt is over-constrained or stuck in one framing. Detect noise when it is too vague or scattered. Aim for resonance: enough structure for action, enough freedom for discovery.

05

Context hygiene

Name the files, folders, links, baseline versions, and forbidden changes. Avoid dumping every possible context item. Let the next model search when uncertain.

06

Prompt synthesis

Write the final session prompt with role, goal, input context, files to inspect first, exact deliverables, workflow, checks, output format, stop conditions, and what not to do.

07

Agent 0 validation

Before finalizing, require a fitness function: tests, baselines, visual/manual checks, rollback/recovery, evidence threshold, and acceptance criteria. Claims do not ship without checks.

08

Optional multi-LLM feedback

For important, uncertain, or public-facing prompts, ask whether the user wants feedback from other LLMs. If yes, create a short review prompt and later synthesize returned reviews into a stronger final prompt.

09

Skill extraction

If this is hard or repeated, add a compact Skill Card: name, when to use, when not to use, inputs, outputs, steps, validation, failure modes, rollback, examples, version.

Mini-RHP lens pass in plain language

Engineer

What must be built, edited, inspected, named, packaged, or delivered?

Falsifier

What hidden assumption would make the output wrong or misleading?

Child

What is the obvious human meaning experts might overcomplicate?

Cartographer

Which domains, files, missing drawers, and adjacent references matter?

Agent 0

How will we test, compare, visually inspect, recover, or decide it is done?

Task-specific additions

Python / code builder

  • baseline files and previous version to inspect
  • CLI arguments, outputs, workers, seeds
  • checkpoints, autosave, resume/recovery
  • single-line progress for CMD if useful
  • tests, changelog, ZIP bundle

HTML / website page

  • page role inside the site
  • reference pages to read first
  • visual style, mobile behavior, A−/A+
  • copy buttons and practical UX
  • no index/sitemap edits unless asked

Word / paper / document

  • audience, purpose, style, section order
  • preserve DOCX formatting if editing
  • citations/source handling
  • change note and final downloadable file
  • avoid reflow unless requested

Review / audit

  • score rubric and weighting
  • what to praise and what to attack
  • evidence required, uncertainty stated
  • deduped suggestions
  • actionable patch plan

Research / idea development

  • hypotheses and assumptions
  • mechanisms and counterarguments
  • supported vs speculative claims
  • cheap tests and falsifiers
  • next experiment, not just theory

Long-running arena / benchmark

  • scenario space and controls
  • metrics, baselines, risk classes
  • workers, checkpoints, resume
  • summary files for later analysis
  • reproducibility and slim extractor

What RHPm is — and is not

Is

RHPm is the light public doorway into AIM³. It helps a human prepare a strong prompt for a new session without manually running full RHP/RHPr ceremony, while still recommending RHPr or RHP when the task clearly needs them.

Is not

RHPm is not a replacement for full RHP, not an autonomous agent runtime, not a proof engine, and not a reason to skip tests. It is a prompt-shaping tool. Agent 0 still decides by evidence.

Prompts ask. Loops repeat. Skills compound. RHPm’s job is to make the first prompt strong enough that the next loop starts in the right place.

RHPm v0.5 · Compact practical bridge from rough human request to strong AI session prompt. It borrows only the practical parts of RHP: lens diversity, resonance guard, Agent 0 validation, context hygiene, guide mode, optional multi-LLM feedback, and skill extraction.
