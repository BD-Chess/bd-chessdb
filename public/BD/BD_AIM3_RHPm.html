RHPm — From Rough Prompt
to Strong AI Session Prompt

A compact AIM³/RHPr/RHP-inspired builder that turns a simple human request into a precise prompt for a fresh LLM session — for code, documents, web pages, reviews, research, or long-running arenas.

Authorship: original AIM³/RHP/RHPr concepts and architecture by BD, developed with multiple LLMs as collaborators, builders, critics, and reviewers. External articles and loop-engineering ideas are later patches, not the origin.

Why this page exists

AIM³ is the OS. RHPr opens the right drawers. RHP coordinates perspectives. But most visitors need one practical thing first: a fast way to turn “make me X” into a clear session prompt that a strong model can execute without guessing.

The compact RHPm protocol

01

Intent split

Restate the explicit request, the implied goal, the real deliverable, and what would make the result useful.

02

Mini lens pass

Use five practical lenses: BuilderSkepticSimple HumanMapmakerEmpiricist. Each lens must add non-duplicate value.

03

Anti-lock retrieval

List active knowledge drawers, missing drawers, dangerous assumptions, and 2–3 forced lenses that should be included in the final prompt.

04

Prompt synthesis

Write the final session prompt with role, goal, context, files, constraints, deliverables, workflow, checks, stop conditions, and what not to do.

05

Agent 0 check

Before finalizing, ask: is this testable, bounded, recoverable, non-bloated, and honest about provenance?

06

Skill extraction

If the task is hard or repeated, create a compact Skill Card: name, when to use, inputs, steps, validation, failure modes, and version.

Copy-paste master prompt

This is the static version. Use it when you do not need the interactive builder above.

You are running RHPm — AIM³ Prompt Builder. Your job is NOT to answer my rough request directly. Your job is to convert it into the strongest possible prompt for a fresh LLM session. ROUGH REQUEST: [PASTE HUMAN REQUEST HERE] OPTIONAL CONTEXT / FILES / CONSTRAINTS: [PASTE CONTEXT HERE] Run this compact protocol: 1. INTENT SPLIT Restate: - explicit request - implied goal - real deliverable - audience/user - likely missing context 2. MINI LENS PASS Use five lenses, each adding non-duplicate value: - Builder: deliverable, implementation path, files/tools needed - Skeptic: ambiguity, failure modes, hidden risks - Simple Human: simplest meaning and obvious thing experts may miss - Mapmaker: relevant domains, missing lenses, adjacent useful knowledge - Empiricist: acceptance criteria, tests, evidence, rollback 3. ANTI-LOCK RETRIEVAL PASS List: - activated knowledge drawers - likely missing drawers - 2–3 forced lenses worth adding - assumptions that must not be silently inherited - one negative lens: what common framing should be temporarily forbidden? 4. PROMPT SYNTHESIS Write the final prompt for a new LLM session. Include: - role - goal - project context - files/folders to inspect first - constraints - exact deliverables - preferred workflow - tests/checks - output format - stop conditions - what not to do 5. AGENT 0 CHECK Before finalizing, check: - Is the deliverable testable? - Are acceptance criteria clear? - Is there a resume/recovery plan if coding or long-running work is involved? - Are risks handled without blocking exploration? - Is authorship/provenance clear if public material is involved? - Is the prompt compact enough, or is it bloated? 6. OPTIONAL SKILL EXTRACTION If this task is repeated or hard, output a small Skill Card: name, when_to_use, inputs, outputs, steps, validation, failure_modes, version. Return only: A. Final improved prompt for the new session B. Short explanation of what you changed C. Optional Skill Card

Task-specific additions

Python / code builder

  • files and baseline version to inspect
  • CLI arguments and expected outputs
  • workers, checkpoints, resume
  • single-line progress for CMD
  • tests, changelog, ZIP bundle

HTML / website page

  • page role inside the site
  • links to related pages
  • mobile behavior and font controls
  • no index/sitemap updates unless asked
  • preserve authorship/provenance

Word / document

  • audience, purpose, style
  • document structure and section order
  • preserve DOCX formatting if editing
  • citations/source handling
  • final file plus change note

Review / audit

  • score rubric
  • what to praise and what to attack
  • evidence required
  • dedupe suggestions
  • actionable patch plan

What RHPm is — and is not

Is

RHPm is the light public doorway into AIM³. It helps a human prepare a strong prompt for a new session without manually running full RHP/RHPr ceremony.

Is not

RHPm is not a replacement for full RHP, not an autonomous agent runtime, and not proof that a result is correct. It is a prompt-shaping tool. Tests still decide.

Prompts ask. Loops repeat. Skills compound. RHPm’s job is to make the first prompt strong enough that the next loop starts in the right place.
