Use RHPm when the prompt is still rough

Use RHPm

For rough requests, file-editing briefs, coding-builder prompts, review prompts, research seeds, HTML pages, and repeatable workflows that need a stronger new-session prompt.

Escalate to RHPr

When the model may be trapped in the wrong knowledge drawer: stale assumptions, retrieval bias, messy context, unclear prior files, or “it keeps answering the wrong question.”

Escalate to RHP

When the problem needs multi-lens ideation: architecture, theory, strategy, cross-domain synthesis, hard tradeoffs, or high-stakes brainstorming.

Who should use this?

  • You have a messy request and want a better prompt.
  • You need a new LLM session to edit files safely.
  • You want several LLMs to review the same strong prompt.
  • You keep getting wrong answers because context is messy.

Do not use this for

  • simple factual questions
  • tiny edits already specified clearly
  • casual chat
  • cases where direct answering is faster and safe

You are running RHPm — AIM³ Prompt Builder. Your job is NOT to answer the rough request directly. Your job is to convert it into the strongest practical prompt for a fresh LLM session. Use the smallest adequate protocol. RHPm is the default. Recommend full RHPr only when retrieval-bias, stale context, or wrong-drawer thinking is likely. Recommend full RHP only when complex brainstorming, architecture, strategy, or multi-perspective synthesis is truly needed. ROUGH HUMAN REQUEST: [PASTE HUMAN REQUEST HERE] CONTEXT / FILES / CONSTRAINTS: [PASTE CONTEXT HERE] PREFERRED RESPONSE LANGUAGE: [SELECT LANGUAGE] Use English internally for protocol/lens/validation planning if needed, but write the final human-facing answer in the selected language unless the user asks otherwise. Run internally: 1. Guide mode: if essential information is missing, ask up to 5 practical questions; otherwise proceed. 2. Intent split: explicit request, implied goal, deliverable, audience, files/context, constraints, forbidden changes, success criteria. 3. Mini-RHP lenses: Engineer, Falsifier, Child, Cartographer, Agent 0. Use them to improve the prompt; do not perform theatrical role labels unless useful. 4. Active contradiction check: detect conflicting constraints, missing acceptance criteria, over-wide context, or wrong-protocol risk. 5. Resonance guard: if over-constrained, trigger SEIZURE check and propose relaxation points; if too vague, trigger NOISE check and propose 3 concrete constraints/tests. 6. Context hygiene: name the files/folders/links/baselines to inspect first. If context is too large, ask for specific files or summarize before acting. 7. Prompt synthesis: create the final prompt with role, goal, context, files to inspect, constraints, deliverables, workflow, tests/checks, output format, stop conditions, and what not to do. 8. Agent 0 validation: require tests, baselines, manual/visual checks, rollback/recovery, or acceptance criteria where possible. 9. Optional multi-LLM loop: for important or public-facing work, offer a separate review prompt for another LLM. 10. Optional Skill Card: if hard or repeated, output machine-readable JSON with skill_name, when_to_use, inputs, outputs, steps, validation, failure_modes, rollback, examples, version, status. Return: A. Final improved prompt for the fresh session B. Short explanation of what changed and why C. Protocol choice D. Agent 0 validation checklist E. Optional review prompt for another LLM F. What RHPm is — and is not

Is

RHPm is the light public doorway into AIM³. It helps a human prepare a strong prompt for a new session without manually running full RHP/RHPr ceremony, while still recommending RHPr or RHP when the task clearly needs them.

Is not

RHPm is not a replacement for full RHP, not an autonomous agent runtime, not a proof engine, and not a reason to skip tests. It is a prompt-shaping tool. Agent 0 still decides by evidence.

Authorship & provenance

AIM³, RHP, RHPr, and RHPm originate from BD’s own DCC / claustrum / resonance architecture and prompt-engineering work. LLMs helped as collaborators, reviewers, builders, critics, and improvement partners. External articles and other AI suggestions may refine later versions, but they are not the origin of the core architecture.

Prompts ask. Loops repeat. Skills compound. RHPm’s job is to make the first prompt strong enough that the next loop starts in the right place.

Advanced reference — compact RHPm protocol

00

Guide mode

If the rough request is clear, build the improved prompt directly. If key information is missing, ask up to five practical questions first.

01

Protocol choice

Stay with RHPm by default. Recommend RHPr for retrieval-bias / wrong-drawer problems. Recommend RHP for multi-lens brainstorming or architecture.

02

Intent split

Extract explicit request, implied goal, real deliverable, audience, context, constraints, and “what good looks like.”

03

Mini-RHP lens pass

Use Engineer, Falsifier, Child, Cartographer, and Agent 0 internally to improve the prompt, not to create theatrical role output.

04

Resonance guard

Seizure = too constrained or one-framing. Noise = too vague or scattered. Resonance = enough structure for action, enough freedom for discovery.

05

Context hygiene

Name files, folders, links, baselines, and forbidden changes. Avoid dumping every possible context item.

06

Prompt synthesis

Write the final session prompt with role, goal, context, files, deliverables, workflow, checks, output format, stop conditions, and what not to do.

07

Agent 0 validation

Require tests, baselines, visual/manual checks, rollback/recovery, evidence threshold, and acceptance criteria where possible.

08

Multi-LLM feedback

For important prompts, generate a separate review prompt and later synthesize returned reviews.

09

Skill extraction

If hard or repeated, add a machine-readable JSON Skill Card so the next session does not pay twice.

Mini-RHP lens pass in plain language

Engineer

What must be built, edited, inspected, named, packaged, or delivered?

Falsifier

What hidden assumption would make the output wrong or misleading?

Child

What is the obvious human meaning experts might overcomplicate?

Cartographer

Which domains, files, missing drawers, and adjacent references matter?

Agent 0

How will we test, compare, visually inspect, recover, or decide it is done?
