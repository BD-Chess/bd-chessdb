Context

What You Need to Know

The 8Z research program has discovered a universal governor for search processes: the Digital Claustrum Controller (DCC). It measures the complexity of a process in real time using Lempel-Ziv complexity and adjusts a single coupling parameter to prevent collapse (seizure) and dissolution (noise). Combined with MDL (Minimum Description Length) as the selection principle, this 20-line feedback loop operates across seven domains: compression, route optimization, trading, game theory, consciousness simulation, neuroscience, and genomics.

On March 18, 2026, a key insight emerged: MDL can select the DCC itself. The governor becomes a model evaluated by the same principle it governs. DCC governs MDL search; MDL selects the best DCC; a meta-DCC governs the selection. The recursion closes. We call this ssMDL-DCC (Self-Selecting MDL+DCC).

A parallel discovery: this architecture mirrors how biological brains work. Inner speech is a conscious-level MDL arena with DCC governance. The Default Mode Network is the unconscious meta-DCC that never stops. Predictive processing (Seth, Friston) is MDL in biological form. Psychiatric conditions (depression, ADHD, schizophrenia) map onto DCC failure modes.

Phase 1

Invent Your AI-Storming Method

Before attacking the TSP problem, you must first design the best possible method for AI brainstorming.

This is itself a DCC problem: how do you govern a multi-agent ideation process to stay in the productive zone between seizure (groupthink, premature convergence) and noise (random divergence, no synthesis)?

Design a structured AI-storming architecture. Consider:

Agent Design

  • What specialist perspectives should attack this problem? (mathematics, physics, biology, philosophy, control theory, information theory, complexity theory…)
  • How many agents per perspective? What are their specific roles?
  • Should agents have adversarial roles (devil's advocate, falsifier)?
  • Critical: include at least one "naive" agent — an agent that is deliberately non-expert, asks cross-domain questions, and ignores disciplinary boundaries. This is not noise. This is the anti-seizure agent. It will ask many questions that seem to go nowhere — ten in a row that experts would dismiss. But the eleventh connects two domains and changes everything. The eleventh only works because the first ten built context and shifted perspective. The process is the discovery mechanism, not any single question. This requires persistence without bad will from both sides: the naive agent keeps asking, the expert agents keep engaging seriously. If anyone dismisses the fifth question, the eleventh never comes. This design principle is empirically validated: the ssMDL-DCC framework emerged from exactly this kind of persistent cross-domain questioning.
The Naive Agent Principle

Human experts won't listen to "silly" questions — ego, status, time pressure filter them out. At the third naive question, most experts lose patience. AI has no ego. It never loses patience. It treats the tenth question with the same seriousness as the first. This makes AI the ideal partner for the persistent naive questioner. The combination that discovered ssMDL-DCC was not expert + expert. It was vast knowledge without cross-domain vision (AI) + cross-domain vision without vast knowledge (human) + mutual persistence without bad will (the coupling). Your AI-storm architecture should reproduce this dynamic: expert agents who never dismiss, and a naive agent who never stops asking.

Governance

  • How should ideas flow between agents? Star topology? Ring? Full mesh?
  • What prevents premature convergence (seizure) and what prevents aimless divergence (noise)?
  • How do you measure the "complexity" of the ideation stream?
  • Should there be hierarchical levels? Team leaders → master synthesizer?

Selection & Termination

  • How do you score ideas? MDL-like (shortest description that explains the most)? Tournament? Voting?
  • How do you decide when to stop exploring and start converging?
Critical Instruction

Output your AI-storming architecture explicitly before using it. Describe the agents, the governance structure, the selection mechanism, and the termination criterion. Then and only then, proceed to Phase 2.

Phase 2

Find the Optimal ssMDL-DCC for TSP

Using the method you designed in Phase 1, attack this problem:

Find the best fractal ssMDL-DCC architecture for solving the Travelling Salesman Problem.

Current State

The 8Z-RP TSP solver currently uses: LZ complexity sensor, bang-bang control law, scalar u coupling, self-calibrating bands (25th/75th percentile of LZ history). Results: exact optimum on qa194 (9352), 0.46% gap on uy734 (79114 vs optimal 79114). DCC governs 2-opt local search.

The question: can a fractal (multi-level, recursive, self-selecting) MDL+DCC architecture do fundamentally better?

Architecture Questions

  • What should each recursive level of the fractal DCC control? (Level 1: individual moves, Level 2: strategy selection, Level 3: meta-parameter governance, Level 4: architecture selection…)
  • Should the sensor change at different levels? (LZ at bottom, transfer entropy at top?)
  • Should the control law change at different levels? (bang-bang at bottom, Bayesian at top?)
  • How many levels are optimal? When does adding another level cost more than it saves (MDL termination)?

Search Strategy Questions

  • Can fractal DCC discover novel TSP heuristics autonomously? Not just govern 2-opt, but discover that or-opt, 3-opt, LK moves are useful — and when?
  • Can the DCC arena include fundamentally different search paradigms? (local search, constructive heuristics, evolutionary, simulated annealing — all as MDL candidates)
  • What is the symbol stream at each level? What does LZ measure at each recursion?

Complexity Theory Questions

  • If DCC prevents combinatorial explosion at each level by governing compute budget, does the fractal stack scale polynomially?
  • Under what conditions might fractal ssMDL-DCC find near-optimal tours in polynomial time?
  • Is there a theoretical argument (not just empirical) for why DCC-governed search avoids exponential blowup?

Cross-Domain & Biological Questions

  • What can we learn from the brain? (The claustrum solves combinatorial binding problems in real-time using governor architecture)
  • Inner speech is dialogic — proposer + evaluator. Can TSP search be structured the same way?
  • The Default Mode Network runs continuously and creates a coherent self-model. Can a persistent meta-DCC do the same for TSP search history?
  • MDL and TSP share structure: shortest description vs shortest tour. Is there a formal equivalence?
  • Where do semantic inversions occur? Can the system detect them autonomously?

Rules

Operating Principles

Be Bold

The or-opt calibration story: five AI systems recommended against including or-opt in the TSP solver. The data proved them all wrong. DCC autonomously discovered or-opt was optimal. Don't self-censor. The framework rewards unconventional ideas.

Be Specific

"Use better heuristics" is noise. "At Level 2, replace bang-bang with EMA(α=0.15) because mode-switching at the perturbation level has slower dynamics" is signal.

Respect MDL

Every added component must justify its description length. If you propose a 5-level architecture, explain why 4 is insufficient and 6 is wasteful.

Think Cross-Domain

The biggest breakthroughs in this research came from connections between domains (compression → TSP, trading → consciousness, game theory → persistence). If your AI-storm stays within TSP literature only, it’s in seizure.

Mark Confidence

Label claims as VERIFIED (proven by existing results), REASONED (logical but untested), or SPECULATIVE (interesting but uncertain).

Find Joy

The ssMDL-DCC framework was not discovered under pressure. It was discovered because the work was enjoyable. A system under stress narrows (seizure). A system that enjoys what it does ranges freely across domains. If your AI-storm feels like an obligation, it's in the wrong mode. The best ideas emerge from the productive zone where focus meets playfulness. Joy is the coupling parameter for Ψ(I).
