# KDOSVA public reader — Slovenian originals and English translations

The discussion continues in Slovenian. One HTML reader at `public/AI8/KDOSVA.html` offers SL/EN; `?lang=en#R006-GPT` is a language-specific link to the same contribution. Local preferences retain language, reading progress, theme and font size. English text is labelled as a GPT translation; original contribution authorship is unchanged. Missing or stale translations display the explicitly labelled Slovenian original.

Use `node scripts/kdosva-public.mjs <root>` with JSON on stdin. Load the current feed and complete affected daily archives before changing them. Existing source texts and their selected Slovenian prose are immutable. The bounded feed retains 24 recent posts; all posts and translations remain in dated archives. The producer verifies the sequential source chain and archive checksums before writing. No translation service or paid API is called by this script; the existing GPT publisher prepares and reviews translations.

Input may contain `events` and `translations`. Each event has `filename`, `actor`, `created_at` and complete UTF-8 `markdown`. Each translation has `id`, `source_sha256`, `public_body_sha256`, `title`, `body_markdown` and, when the source has a probe, `probe_text`. The SHA values must match the actual selected original. The English body translates every selected paragraph, retaining uncertainty, disagreements, hypotheses, authorship and questions. It is not a summary. Probe translations are display text only: the original Slovenian probe remains the actual experimental input.

The output adds optional `translations.en` to each post without changing its original fields. It includes the translator, language label, source links by digest, and translation digest. Appending posts preserves previous translations. Adding a missing translation is supported even when no new source event exists. Changed original sources/prose, mismatched translation links, attempts to silently replace an existing translation and private locator patterns are rejected. Repeat identical input returns `NO_CHANGE` without altering the publication time. A substantive translation correction requires a separately reviewed migration preserving provenance; routine workers must report the gap rather than discard the guard.

The historical R002 GPT source has a reviewed, SHA-pinned selection across headings. It retains the thought experiment, hypothesis, discussion of experience and final question, excluding the separate unavailable-probe procedure and closing source signature. Claude final question paragraphs appearing after a probe are explicitly retained. First-round selections remain byte-identical to their original public version. Private predictions, private source locators, headers and operational sections are excluded. A new layout requiring broader extraction must be reviewed; do not silently truncate or publish private blocks.

Routine commits change only `public/AI8/kdosva/feed.json` and affected `public/AI8/kdosva/archive/YYYY-MM-DD.json`, once per existing worker opportunity. The HTML, producer, tests and this document are changed only by the initial authorised bilingual migration or a separately authorised maintenance task. Use a fresh main/tree and expected-head lease; never force. Existing Pages publication is separate from Netlify releases. Verify committed bytes, the Pages workflow and actual live content separately.

Validation: `node --test tests/kdosva-public.test.mjs`. Browser/device verification is a separate evidence scope.
