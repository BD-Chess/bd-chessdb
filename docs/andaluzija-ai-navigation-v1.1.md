# Andaluzija AI v1.1 — navigation and richer knowledge

The travel assistant had POI and external Maps tools but no way to move the current HTML page. Requests such as “premakni mi HTML stran na mesto kjer je zemljevid” therefore produced a refusal or a Google Maps link. The page now executes clear navigation commands locally without a paid model call, and both GPT and Claude also receive the constrained `show_page_section` tool for other phrasing.

Navigation accepts fifteen compiled section IDs and an optional day card 1–10. It verifies visibility before returning `shown`, retains the conversation, and closes the overlapping sidebar below 1100px. A return button restores it. It does not sync, write, solve, unlock, or send DOM content to the model. Locked private sections remain placeholders. The encrypted continuation checks the navigation receipt against the requested target and session epoch.

The public skill is now 1.1.0: ten enriched city references, six specialist topics (regional context, public itinerary, page help, food/culture, practical travel, tickets/access), an action contract and 84 public visit candidates. The same hashed package is bundled for both providers. Topics load on demand. Public official tourism/operator sources were checked on 21 October 2026; future hours, prices, availability and weather remain unverified. No personal itinerary data or credentials were added to the skill.

Validation: 30 targeted application/auth/tool/knowledge checks pass; real local Chromium at 1440, 900 and 402px passes the literal map command, day navigation, locked private destination, GPT and Claude tool continuations, conversation restoration and unchanged plan. Provider transport uses deterministic fixtures, with zero paid provider calls. A separate brief skill exercise correctly used the map tool, adapted a short Córdoba visit, compared day eight and withheld an unconfirmed save claim.
